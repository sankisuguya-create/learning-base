# learning-base

学習アプリ（算数タイムアタック・漢字の森・といボード・アンケートなど）が共通で使う部品の正本。
設計は `-` リポジトリの `principles/learning-app-foundation.md`、配り方は同 `principles/jsdelivr-delivery.md`。

**このリポジトリは公開。名簿・記録・児童名など個人情報を置かない。**

## 学習BASE を動かす（GAS に貼るのは `gas/Loader.gs` の1枚だけ）

読み込み係（`Loader.gs`）が、共通部品・各アプリのサーバー側のコード（`dist/server.js`）と画面のファイル（`dist/html.json`）を
jsDelivr から版で固定して取ってきて実行する。

**更新は PR のマージだけ。** main にマージされると GitHub の自動処理（`.github/workflows/release.yml`）が検査を通した上で
`release.json`（版と指紋）を書き、読み込み係が5分以内にその版を使い始める。検査が落ちれば `release.json` は変わらない（学校は前の版のまま）。
**戻す・止める時**は、ハブの `platform` シートの「版」にコミット番号を書く（その版で固定）。「自動」と書くか空にすれば、再び `release.json` を追う。

### 設置（1回だけ・校務PC）

1. スプレッドシートを作り（または算数TA をまとめた今の GAS を使い）、「拡張機能 → Apps Script」で `gas/Loader.gs` の中身を `コード.gs` に貼る。他のファイルは消してよい
2. プロジェクトの設定 → スクリプト プロパティ → `HUB_ID` にハブのスプレッドシートの ID
3. エディタで `lbSetup` を実行（承認・自動実行の設置・技能の目録をハブに書く。実行ログに結果）
4. デプロイ → 新しいデプロイ → ウェブアプリ（次のユーザーとして実行：自分、アクセス：ドメイン内の全員）

（`platform` シートは要らない。版を固定したい時だけ作る：A1「版」・B1 にコミット番号、A2「指紋」・B2 に `dist/manifest.json` の `server`）

### 更新

- PR をマージする。反映は最大5分（すぐ反映するにはエディタで `lbReload`）
- 戻す時はハブの `platform` シートの「版」に前のコミット番号を書く（固定）。直ったら「自動」に戻す
- 状態はエディタで `lbStatus`（実行ログに版と「自動／固定」）

### 取ってくる順（実測 2026-11-09）

一時保存（約120ms）→ jsDelivr（約1.4秒・版を変えた直後の1回）→ ハブの `platform_code` シートの写し（jsDelivr が止まった時）。
1時間ごとに一時保存を温め直す（`lbHourly`）。

### URL

| URL | 開くもの |
|---|---|
| `…/exec` | 学習BASE のホーム |
| `…/exec?app=tamath&unit=kuku` | 算数タイムアタック（`?unit=kuku` だけでも開く） |
| `…/exec?doc=<id>` | 教材・授業ページ（準備中）。`page=` はアプリが使う（算数TA の教師画面 `page=teacher`） |

### アプリを載せる・更新する（Claude の作業）

- `apps.lock.json` にアプリのリポジトリ・コミット・サーバー側のファイル・画面のファイルを書き、`npm run bundle` で `dist/` を作る
- アプリのサーバー側のコードは関数の中に包んで実行する（アプリの `doGet` などが読み込み係の入口を上書きしないように）。
  包んだ中で動くための口（`LB_FILES`・`LB_APP_QUERY`・`LB_RESOLVE_`・`LB_PLATFORM_TRIGGERS`）を、アプリ側が使う（算数TA の Core.gs の「学習BASE の中で動く時」）

## gas/Base.gs（段階1）

各アプリの GAS に、このファイルを `Base.gs` としてそのまま貼る。名前はすべて `Base.` の下にあり、アプリの大域名とぶつからない。

| 呼び方 | 返すもの |
|---|---|
| `Base.VER` | 版。やりとりの形を変えたら上げる。アプリは期待する版と比べて、貼り忘れを画面に出す |
| `Base.me()` | 開いた人 `{ email, role, child, teacher }`。role は `teacher` / `child` / `guest`（名簿にない・名前なし。記録しない）/ `none`（メールが取れない） |
| `Base.roster(年度?)` | 名簿 `[{ mail, grade, cls, no, sei, mei, seiKana, meiKana, name }]`。年度を省くと今年度 |
| `Base.child(mail)` | 名簿にあって名前のある児童。無ければ `null`（見つからない時は10分に1回まで名簿を読み直す） |
| `Base.learner(lid)` | 学習者IDで児童を引く（メールの無い転入生も引ける） |
| `Base.members(学年, 組)` | 学級の児童（番号順）。教師が「だれが やる？」を選ぶ画面に使う |
| `Base.actAs(lid)` | 教師が児童の代わりに取り組む。担当の学級の児童だけ。`{ learner, by }` を返す |
| `Base.canSeeClass(mail, 学年, 組)` | その教師がその学級の児童名つきの記録を見てよいか |
| `Base.fy()` / `Base.fyOf(時刻)` | 年度（4/1 はじまり、日本時間） |
| `Base.classKey(学年, 組)` | 学級のキー `"3-1"`（組の表記ゆれを揃える） |

エディタから実行する関数：`baseSetHub('ハブのURL')`（アプリごとに1回）、`baseClearCache()`（名簿を直した後）。

### ハブの表

**roster**（今年度の名簿。過去年度は `roster_2026` のように年度を付けて残す）

| メール | 学年 | 組 | 番号 | 姓 | 名 | せい | めい | 学習者ID |
|---|---|---|---|---|---|---|---|---|

- 見出しの名前で列を探すので、列の順は自由。
- 旧形式（`email | 学年 | 組 | 番号 | 氏名`）もそのまま読める。氏名は空白で姓・名に分ける。
- `せい`・`めい`（ひらがな）は、Gemini 用の書き出しで名前を記号に置き換える時に使う。それまでは空でよい。
- 組は「1」「1組」「１」をすべて「1」として扱う。
- **学習者ID は Base.gs が自動で書き足す。教師は書かない・書き換えない**（書き換えるとその児童の記録が別人になる）。
  乱数で作るので、名前・メール・番号などから導けない。前の年度の名簿（`roster_<年度>`）に同じメールがあれば引き継ぐ。
- **メールがまだ無い転入生は、メールを空にして姓・名・学年・組・番号を書く。** 学習者ID が付き、教師の端末から「代わりに取り組む」で記録できる。
  メールが割り当てられたら、その行にメールを書き足すだけでよい（学習者ID は変わらず、記録がつながる）。

**teachers**（担当。1人で何行でも書ける）

| メール | 姓 | 名 | せい | めい | 学年 | 組 |
|---|---|---|---|---|---|---|

- 組が空＝その学年の全学級。学年も空＝全校。
- **教師ドメイン（`@edu.nishi.or.jp`）の人は、ここに書かなくても全学級を見られる**（今の算数TAと同じ。2026-11-05 決定）。
- 教師ドメイン以外の人（支援員など）は、ここに書いた担当の学級だけを見られる。
- 担当で絞る運用に変える時は、Base.gs の `STRICT_SCOPE` を `true` にする（教師ドメインの人も担当の学級だけになる）。

### 保存（キャッシュ）

名簿と担当は6時間保存する（`CacheService`。大きな名簿は3万字ずつに分ける）。
直したらすぐ反映させたい時は `baseClearCache()` を実行する。

## 学習の記録（段階A）

| ファイル | 名前 | 役割 |
|---|---|---|
| `gas/Catalog.gs` | `LbCatalog` | アプリが宣言する技能の目録（技能のキー・到達の基準・誤答の型・受け取れる指示）。ハブの `catalog` シートに書く |
| `gas/LbSession.gs` | `LbSession` | 1回の取り組みを1行で記録する（全問を JSON で1セルに＋技能ごとの統計）。アプリの `sessions_<年度>` シートに書く |
| `gas/Facts.gs` | `LbFacts` | 全アプリのセッションを「児童×技能×週」に集計する（毎晩、新しい行だけ読む）。状態（未着手・練習中・到達）を目録の基準で判定する |
| `gas/Pseudo.gs` | `LbPseudo` | 名前を記号に置き換える・戻す（Gemini・NotebookLM に渡す前） |
| `gas/Alerts.gs` | `LbAlerts` | 今週の3件（初期値は `RULES`、変えられる項目は `SPEC`。所有者が変えた値はハブの `rules`）。ハブの `now3`・`decisions` |
| `gas/Tune.gs` | `LbTune` | 直すための材料：使われ方（ハブの `usage`）・出た記録（`now3_log`）・先生の気づき（`feedback`）・記号表（`pseudo_<年度>`）。改善用の書き出し（使い勝手・機能性だけ）と閾値を見直す画面（学校の中だけ）。手順は `docs/tuning-log.md` |

- GAS には組み込みの `Session` があるので、名前はすべて `Lb` で始める
- アプリが書くのは「出題と画面」と「目録」だけ。記録・集計・状態の判定は共通の部品が行う
- 記録・集計・記号は、メールではなく学習者ID で束ねる（メールの無い転入生も記録でき、後でメールが付いても記録がつながる）
- 名前の置き換えの規則は `-` リポジトリ `principles/learning-app-foundation.md` §8。**記号は乱数で振り、計算では求めない**（名前・年齢・ID などから導けない）。
  そのため記号表はハブに保存して使い続ける。保存した記号表（`existing`）を渡すと、転入しても他の人の記号は変わらない

## 学習BASE の入口（段階B）

| ファイル | 役割 |
|---|---|
| `catalog/pages.json` | ページの目録（教科・学年・単元・題・読み・種類・読み込み先）。**Claude が足す。教師は編集しない** |
| `gas/Pages.gs`（`LbPages`） | 児童に見せるページ・いまの学習の判定（学年・公開・期間・最大3件）と、学級の設定の保存（ハブの `class_pages`・`now_learning`） |
| `gas/Home.gs`（`LbHome`） | 画面から呼ぶ窓口 `homeBoot`・`homeSetPublish`・`homeResetPublish`・`homeSetNow`。教師は担当の学級だけ変えられる |
| `web/home.js`・`web/home.css` | 画面（jsDelivr から読み込む）。学習BASE → 教科 → ページ。教師は同じ画面で先生モード（✓ みせる／✕ かくす、★ いまの学習）と、代わりに取り組む児童を選べる |
| `web/pages.js` | `gas/Pages.gs` の写し（`npm run build` が作る）。判定の規則を画面とサーバーで1つにする |
| `web/demo.html` | 見本（GAS なし）。`?role=child3`・`child1`・`teacher`・`guest` |

- 教科は色で見分けない（教科は13あり、色で区別できるのは4つまで。color-coding スキル）。絵と名前で見分け、色は「いまの学習」を目立たせることにだけ使う
- 文字：1・2年はひらがな、3年は題の上に読み、教科名は4年までふりがな

## 検査

```
npm run bundle  # 画面用の写しと dist/ を作る（アプリのクローンは隣のフォルダ、または LB_APPS_DIR）
npm test     # 全部（写し・dist の一致・base・pseudo・learning・pages・platform）
npm run ui   # 画面（Playwright：エラー・中国語フォント・入れ子のボタン・先生モードの保存）
```

GAS を模擬して Base.gs を動かす（年度の境目・ドメインの完全一致・旧新の名簿形式・担当の範囲・大きな名簿の保存）。
