# 教科（アプリ）を学習BASE に足す時の約束

学習BASE が大元。各教科のアプリは、学習BASE の名簿・担当・記録・先生の画面の上に載る。
今は 算数（算数TA）と 国語（漢字の森）。新しい教科も、この約束を満たせば `apps.lock.json` に1行足してマージするだけで学校に届く。

設計：`-` リポジトリ `principles/learning-app-foundation.md` §17。

## 1. 名簿と担当は持たない
- 児童・学習者ID・学級・先生の担当は、学習BASE のデータ（名簿・teachers）だけが持つ。アプリは `Base` を使う：
  `Base.me()`（開いた人と役割）・`Base.child(mail)`・`Base.learner(lid)`・`Base.roster()`・`Base.members(grade, cls)`・`Base.canSeeClass(mail, grade, cls)`・`Base.actAs(lid)`（代わりに取り組む）
- 先生が見られる学級は学習BASE の決まりに従う（教師ドメインの先生は全学級。決定 2026-11-11）
- 記録・集計は学習者ID で束ねる（メールの無い転入生も扱える）

## 2. サーバーのコード
- アプリのリポジトリのファイルを、学習BASE が `dist/server.js` の中で関数に包んで読み込む（`tools/bundle.cjs`）。アプリの名前は大域に出ない
- `apps.lock.json` に書くもの：`repo`・`commit`（版）・`server`（読み込むファイル）・`exports`（学習BASE が呼ぶ関数）・`locals`（包んだ中で使う値）
- 学習BASE が呼ぶ関数（あるものだけ）：`doGet`（ページ）／画面から呼ぶ関数（下の3）／`setup`／`nightly`・`daily`・`rollover`（自動実行。学習BASE の読み込み係が呼ぶので、アプリは自分で自動実行を置かない）／`sessionSources`（記録先。下の4）
- 読み込みの時点で失敗したアプリは、そのアプリだけ止まる（「いまは ひらけません」）。学習BASE とほかのアプリは動き続ける。文法の誤りは閉じ込められないので、マージ前の検査で落とす
- 単体の GAS としても動けるようにしてよい（`typeof Base === 'undefined'` なら自分の流儀）。学習BASE に移る間、今の URL を残すため
- アプリのデータ（進み具合など、アプリの中だけのもの）は、アプリのスプレッドシートに置いてよい。学習BASE の名簿の写しは置かない

## 3. 画面
- 小さい画面：テンプレートとして `dist/html.json` に入れ、`doGet` が返す（算数TA）
- 大きい画面（数十万字以上）：アプリのリポジトリのファイルを jsDelivr から読む（版はコミットで固定。`@main` は使わない）。2回目からはブラウザに保存した分を使うので開くのが速い
- 画面からサーバーを呼ぶのは `google.script.run` の代わりの差し替え（学習BASE が渡す）を通す。呼べるのは `exports` に書いた関数だけ
- 学習BASE の目録（`catalog/pages.json`）に、教科・学年・題・`kind: app`・`app`（アプリの id）を書く

## 4. 記録
- 1回の取り組みごとに `LbSession.write` で書く（`gas/LbSession.gs`）：学習者ID・アプリ・活動・文脈（`live`＝本番／`practice`＝練習）・1問ごと（技能・一度で正答したか・時間）
- 技能の目録（`LbCatalog`）を出す：技能のキーは `教科/アプリの中の名前`（例 `math/kuku/A`）。到達の基準。受け取れる指示（`directives: ['weight']` など）
- 集計（児童×技能×週）・今週の3件・指示は、この記録と目録だけを読む。アプリごとの作り込みは要らない
- 練習（`practice`）は集計に入れない（本番の記録で比べるため）

## 5. 先生の画面
- 先生の入口は学習BASE の1つ。共通（公開・いまの学習・並び・色・開く先・今週の3件・指示・児童の一覧・児童カード）は学習BASE が持つ
- アプリごとの設定（漢字の出題順など）は、アプリが「設定の欄」を学習BASE の画面に渡す（約束の形は段階4で決めて、ここに書く）
- アプリの詳しい分析は、アプリのページとして残してよい。学習BASE の先生の画面から入れるようにする
- 教科をまたいだ合計点・順位は作らない。教科ごとの指標を並べて見る（決定 2026-11-11：成績には使わない。参考に見る程度）

## 6. 検査と反映
- アプリのリポジトリの検査が通っていること
- 学習BASE の `apps.lock.json` の版を書き換え、`npm run bundle` → `npm test`（通しの検査が `dist/server.js` を実際に読み込む）
- マージすると GitHub Actions が、アプリを固定の版で取ってきて検査し、`release.json` を書く。学校の読み込み係はそれに従う
