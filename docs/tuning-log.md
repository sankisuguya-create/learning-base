# 学習BASE を直す手順と記録

設計：`-` リポジトリ `principles/learning-app-foundation.md` §15。実装：`gas/Tune.gs`。

## 線引き（決定 2026-11-10）

Claude に渡すのは **学習BASE の使い勝手・機能性** だけ。児童の学習状態（個人も集団も）は渡さない。

| 何を直すか | どこで | 材料 |
|---|---|---|
| 画面・機能・速さ・失敗 | Claude（PR → マージで反映） | 改善用の書き出し・撮影用の画面写真・先生の気づき |
| 今週の3件の閾値 | 学校の中（所有者が学習BASE の「閾値を見直す」で値を変える。ハブの `rules` シートに保存、翌晩から効く） | 候補の数・1つずつ変えたら・分布・出た件数（画面の中だけ） |

## 使い勝手を直す（Claude と）

1. **書き出す**（所有者・校務PC）：先生の画面の一番下「改善用に書き出す（使い勝手・機能性）」。
   - 中身：使われ方・速さと失敗・今週の3件への先生の反応（割合だけ）・先生の設定（閾値を初期値から変えたかも）・先生の気づき。
   - 「目で確かめる」が出たら読む（気づきに名前があった・1文字の名前を置き換えていない）。学習のようすが書かれた気づきは、ハブの `feedback` で書き直してから書き出し直す。
   - 「書き出しを止めました」は、名前・メール・学習者ID が残った時。文は出ない。
2. **画面写真**は、先生の帯の「撮影用」を押してから撮る（配置はそのまま、名前と数字が見本になる。ページは開かず、押しても記録しない）。
3. **渡す**：文を貼る・写真を送る → Claude が直し方と根拠（どの表のどの数か）、次の書き出しで何が変われば効いたと言えるかを示す → PR → マージ。
4. 下の記録に1行（Claude が PR に入れる）。2〜4週後に次の書き出しで確かめる。

## 閾値を直す（学校の中で）

1. 所有者：先生の画面の一番下「閾値を見直す（学校の中だけ）」。
2. 値を変えて「この値で数える」→「入れた値なら」の行で、今週の候補の数を比べる。「1つずつ変えたら」と散らばりの表も見る。
3. 「保存する」（今夜から）か「保存して今すぐ計算し直す」。「すべて初期値にもどす」で戻せる。
4. 目安（初期値。根拠なし）：学級あたりの候補が「学級ごとに出す数」を大きく越える規則は、下位が出ないので厳しくする。
   書き出しの「先生の反応」で「見た」ばかりで「変わった」が少ない種類は、当たっても手を変えるほどではない（厳しく）。「押されていない」が多い時は、先生が開いているか（使われ方の boot）を先に見る。

## 書き出しの読み方（Claude 向け）

| 表 | 読み方 |
|---|---|
| 1. 使われ方 | 先生の boot が少ない週は、3. の「押されていない」を当たり外れと読まない。act: の偏りで、使われていない操作が分かる |
| 2. 速さと失敗 | rt の 4秒以上が増えたら、画面かサーバーの処理を見直す。err・client が出たら、その関数を直す |
| 3. 先生の反応 | 「少ない」は出た件数が10件未満（割合を出さない）。種類ごとの割合が閾値の当たり外れの手がかりだが、閾値そのものは学校の中で直す（Claude には数が無い） |
| 4. 先生の設定 | かくしたページ・いまの学習が使われていなければ、その操作の見つけにくさを疑う |
| 5. 気づき | 数で見えない不具合。同じ指摘が2回出たら直す |
