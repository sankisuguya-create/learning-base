# 学習BASE を直す手順と記録

設計：`-` リポジトリ `principles/learning-app-foundation.md` §15。実装：`gas/Tune.gs`。

## 1回の回し方

1. **書き出す**（所有者・校務PC）：学習BASE を開く → 先生の画面の一番下「改善用に書き出す（所有者だけ）」→ 30秒ほど待つ。
   - 「目で確かめる」が出たら読む（1文字の名前を置き換えていない、など）。必要なら元の気づき（ハブの `feedback`）を書き直してもう一度書き出す。
   - 「書き出しを止めました」が出たら、名前・メール・学習者ID が残っている。文は出ない。理由の文をそのまま Claude に伝える（ハブの中身は送らない）。
2. **渡す**：「コピーする」→ Claude に貼る。画面の不具合は、見本ページ（`web/demo.html`）で同じ所を撮るか、「名前をかくす」を押してから撮る。
3. **Claude が提案する**：書き出しの数から、閾値・設定・画面のどこをどう変えるかと、その根拠（どの表のどの数か）、次の書き出しで何が変われば効いたと言えるか。
4. **PR → マージ**：GitHub の自動処理が検査を通して release.json を書く。学習BASE は次に開いた時から新しい版（貼り直しなし）。
5. **下の記録に1行**（Claude が PR に入れる）。
6. **次の書き出し**（2〜4週後。今週の3件は週ごとの数なので、1週では効いたか分からない）で、5. に書いた見る所を確かめる。

## 書き出しの読み方（Claude 向け）

| 表 | 直す時の目安（初期値。根拠なし。回しながら直す） |
|---|---|
| 2. 今週の3件の働き | 「押されていない」が多い種類は、教師が見ていないか、当たっていない。「見た」ばかりで「判断が変わった」が無い種類は、当たっても手を変えるほどではない（閾値を厳しく） |
| 3. 閾値を1つ変えたら | 学級あたりの候補が3件を大きく越える規則は、3件に切られて下位が出ない。いまの値と試す値で数が大きく動く規則は、閾値が分布の山の上にある |
| 4. 分布 | 閾値の区間に児童が集中していれば、少し動かすだけで出る件数が大きく変わる |
| 5. 使われ方 | 先生の boot が少ない週は、2. の「押されていない」を当たり外れと読まない |
| 6. 速さと失敗 | rt の 4秒以上が増えたら、画面かサーバーの処理を見直す。err・client が出たら、その関数を直す |
| 8. 気づき | 数で見えない不具合。同じ指摘が2回出たら直す |

- 人数の「5人未満」は、0 ではない。1〜4人のどれか。
- 3. の数は、判断済みも含み、学級ごとの3件に切る前の数。2. の数は、画面に出した数。
